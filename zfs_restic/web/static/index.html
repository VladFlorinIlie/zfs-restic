Set up or re-authorise Google Drive

      

        
    
          
  1. Create your own OAuth client (rclone's shared one is being retired): in Google Cloud Console create a project, enable the Google Drive API, configure the OAuth consent screen and publish it to "In production" (in "Testing", Google revokes the token after 7 days), then create an OAuth client of type Desktop app. rclone's guide
    2. 
          
  2. Get a token on a machine with a browser and rclone installed (Windows, WSL or Linux): 
    rclone authorize "drive"
     Sign in with the Google account that owns the backups; rclone prints a JSON token.
    3. 
          
  3. Paste it below and save. The current rclone config is kept as a previous version, and the remote is tested straight away.

Empty fields keep the remote's current values, so to re-authorise you only need the token. A token only works with the client it was made with: if you change the client ID, generate a new token with it. Disaster-recovery kit 

      

        
If this server dies, you need three things to get your data back: the repository location, the repository password (without it the backups are unrecoverable by anyone) and access to Google Drive. The kit puts them on one page with step-by-step restore commands and your config.yml.

        
Print it or save it in your password manager, never on the server itself or in the same Google account.
